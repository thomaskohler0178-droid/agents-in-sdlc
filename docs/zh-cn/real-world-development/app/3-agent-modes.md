我们刚刚为项目添加了一个小功能，但更大的改动需要更完善的流程。GitHub Copilot app 可以融入组织现有的工作流程，帮助我们以正确的方式构建正确的内容。在接下来的几课中，你将按照典型的智能体开发流程，从议题开始实现新功能，确保代码有效、功能符合预期，最终成功合并到项目中。

> [!NOTE]
> 后续功能流程会继续使用同一会话。实际工作中，通常会按不同文件类型使用不同会话或 PR；这里会简化流程，以便聚焦核心概念。

本课将：

- 从 GitHub 议题开始新的智能体会话。
- 在 **Plan** 模式下定义需求。
- 使用 **Autopilot** 模式实现新功能。
- 审查代码。
- 在浏览器 Canvas 中手动验证功能。

在继续实现这个功能时，你还将更新存储库说明、自定义现有 quality-checks 技能、添加 MCP 验证、创建 QA 智能体并创建功能 PR。

## 场景

Tailspin Toys 的目录不断扩大，访问者需要按类别和发行商筛选游戏。积压工作中的议题描述了该功能，但例如是否允许组合多个类别等细节需要先达成一致。你将使用 Plan 模式确定这些决策，然后授权 Autopilot 在明确范围内实现。

## 背景

在开发流程中引入 AI 编码智能体并不会改变基本原则。事实上，这些原则可能更加重要！大多数开发人员的工作流程大致如下：

1. 打开描述任务详情的已创建议题。
2. 规划要构建的内容。
3. 编写并审查代码。
4. 运行测试验证代码。
5. 手动验证新功能。
6. 创建拉取请求（PR）。
7. 代码通过审查且持续集成成功后，合并代码。

> [!NOTE]
> 具体流程因团队和组织而异，但大多数流程都与上述方式类似。

遵循这一标准流程，可以确保 AI 生成的代码满足需求，并经过与手写代码相同的验证。

## 会话模式

**会话模式**控制智能体的自主程度。可以在提示输入框下方的下拉菜单中设置，并可随时更改：

- **Interactive**：你与智能体协作。智能体提出变更建议，并等待你的输入后再继续。
- **Plan**：智能体先创建计划。智能体执行计划前，你可以先审查并批准。
- **Autopilot**：智能体完全自主工作，编写代码、运行测试并不断迭代，无需等待输入。

先从 Plan 模式开始并审查计划，然后使用 Autopilot 实现计划。

## 从议题开始会话

开始前，确认星级评分 PR 已合并，并且本地 `main` 已更新。

1. 在侧边栏的 **Sessions** 下，选择 Tailspin Toys 存储库文件夹，然后在存储库顶部导航中选择 **Issues**。打开现有议题 **Allow users to filter games by category and publisher**，无需再创建新议题。
2. 选择 **New session**，并基于已更新的 `main` 选择**新工作树**。

   ![GitHub Copilot app 中指向 New session 按钮的议题视图](../../../_images/app-new-session-from-issue.png)

3. 确认议题已附加到会话，并从模式选择器中选择 **Plan**。

> [!NOTE]
> 如果找不到 Node.js 或 npm，请让智能体运行 `node --version` 和 `npm --version`。如果它们在终端中可用，但在会话中不可用，请检查应用的 PATH 或版本管理器设置，然后完全退出并重新打开应用。重试失败的操作和检查；不要仅仅因为智能体找不到 npm 就重新安装 npm。

## 规划筛选功能

规划可以让你在 Copilot 编写代码前审查实现方案。由于会话从议题开始，Copilot 已经获得了功能需求的上下文。发送以下提示：

```plaintext
Build this feature.
```

回答 Copilot 的问题，并根据议题验收标准审查计划。确认计划涵盖类别和发行商筛选、无障碍控件、数据访问变更和测试。讨论任何不明确的行为，例如多个类别如何组合，或没有游戏匹配时应显示什么。

计划应包括使用项目现有工具运行 lint、单元测试、E2E 测试和类型检查。计划应聚焦于实现并测试筛选功能；质量工作流程完成后再创建 PR。批准计划前，请要求修改不符合预期的部分，并记录议题 URL 及达成一致的说明，以便后续验证。

## 明确批准 Autopilot

确认计划符合预期后，选择 **Approve and implement this plan**，或当前版本中含义相同的选项。检查当前模式，不要假定批准计划会自动切换模式。确认模式指示器显示 **Autopilot**。

Copilot 会开始实现，并根据计划迭代、生成代码和运行测试。

> [!NOTE]
> 批准计划后，实现可能立即开始，因此请先审查计划。如果 Copilot 报告缺少依赖项或端口冲突，请先解决环境问题，再判断检查是否完成。只停止自己启动的服务器。

## 审查并验证实现

代码生成后，和其他代码一样，必须在合并前审查。现在检查代码并运行网站，确认一切正常。

1. 打开 **Changes**，检查筛选功能实现和测试。
2. 将结果与议题及批准的说明进行比较，包括多个类别和发行商组合。确认变更符合现有存储库说明。
3. 检查 lint、单元测试、E2E 测试和类型检查的结果。跳过的检查不算通过。
4. 解决失败项并重新运行受影响的检查，然后再接受实现。Playwright 的 E2E 配置会构建并运行预览服务器，也可能复用本地服务器；确认被测服务器属于此工作树，而不是上一课留下的服务器。

## 探索新功能

代码看起来没问题，但能否正常运行？像之前一样启动应用，并在浏览器 Canvas 中打开网站。

1. 使用以下提示，请 Copilot 启动应用并在浏览器 Canvas 中打开页面：

   ```plaintext
   Start the app and open it in the browser canvas.
   ```

2. 片刻后，应用会启动，Copilot app 内会打开浏览器窗口。
3. 选择类别并确认结果符合类别条件。清除筛选，再选择发行商并确认结果符合发行商条件。
4. 组合类别和发行商筛选，并根据议题和批准的计划比较结果。如果支持多个类别，还要验证约定的组合行为。
5. 测试没有匹配游戏的情况，检查空状态。清除或重置筛选，确认完整列表恢复。
6. 检查完毕后，使用以下提示，请 Copilot 停止此会话启动的开发服务器：

   ```plaintext
   Stop the dev server and close the browser canvas.
   ```

## 保留此会话以供后续课程使用

现在不要创建或合并筛选功能 PR。请保留此会话、工作树和分支，供第 4 至第 8 课继续使用。接下来会将自定义说明应用于筛选代码，然后添加技能和 QA 改进，最后在第 8 课创建并合并综合 PR。停止开发服务器后，可以让会话保持空闲，并在下一课返回同一会话。

- 从 GitHub 议题开始新的智能体会话。
- 在 **Plan** 模式下定义需求。
- 使用 **Autopilot** 模式实现新功能。
- 审查了代码。
- 在浏览器 Canvas 中手动验证了功能。

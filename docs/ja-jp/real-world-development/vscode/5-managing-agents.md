GitHub Copilot を agent mode で使うと、コードベースの調査、変更の提案、ファイルの編集、コマンドの実行などを自律的に行います。VS Code の Copilot Chat では、ツールの呼び出しやファイルの編集をリアルタイムで確認できます。差分をレビューし、個々の変更を受け入れるか元に戻し、追加のプロンプトでエージェントの作業を調整できます。

この演習では、次のことを行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして受け入れます。
- セッション中にエージェントへ指示し、ハイ コントラストに加えてライト モードも追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ カスタム エージェントは、ハイ コントラスト モードを実装しています。作業中にデザイン チームから、既定のテーマが暗すぎると感じるユーザー向けに、ライト モードの切り替えも追加してほしいという要望がありました。新しい会話を始めずに、進行中のセッションに追加の作業を指示します。

## Copilot の進行状況を監視する

Copilot Chat ビューには、エージェントが調査するファイル、実行するコマンド、提案する編集が順番に表示されます。各ファイルの編集は差分と **Keep** / **Undo** の操作とともにチャットに表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、ツールの呼び出しを確認します。ファイルの読み込みや編集、実行を依頼されるターミナル コマンドが表示されます。
3. ファイルの編集が提案されると、差分がチャットに表示されます。
   - **Keep** を選択すると変更を受け入れます。
   - **Undo** を選択すると変更を元に戻し、エージェントに再度作業させます。
4. チャット上部の **Files changed** を開くと、このセッション中にエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ターミナル コマンドの実行などに許可が必要な場合、エージェントは一時停止して **Allow** を表示します。問題ないコマンドだけを許可してください。

5. エージェントがハイ コントラスト モードの実装を終えるまで待ちます。最後に、行った変更の概要が表示されます。

## ライト モードを追加するようエージェントに指示する

ハイ コントラスト モードの実装後、同じ会話でライト モードの切り替えを追加します。同じチャット セッションを続けるため、エージェントは変更したコンポーネント、スタイル、ローカル ストレージのパターンなど、前の作業のコンテキストを保持しています。

1. Copilot Chat の入力欄に、次のプロンプトを送信します。

   ```plaintext
   Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
   ```

2. エージェントは前の作業を引き継ぎ、変更内容を確認してライト モードを追加します。
3. 追加される編集をレビューし、差分ごとに **Keep** または **Undo** を選択します。
4. エージェントが意図しない方向へ進んだ場合 (たとえば、切り替え UI を望まない方法で再構成しようとした場合) は、チャット入力欄の横にある **Stop** を選択して作業を止め、補足のプロンプトを送信します。

> [!TIP]
> 進行中のセッションに指示する方が、やり直すよりも速く進められます。追加のプロンプトで、調整 (「CSS を簡潔にし、セレクターの重複ではなく CSS 変数を使う」)、方向修正 (「3 つ目の切り替えを追加せず、ライト モードを既存の設定パネルに組み込む」)、範囲の拡張 (「両方の切り替えにキーボード ショートカットも追加する」) を依頼できます。

## 変更されたファイルを確認する

commit する前に、エージェントが変更した内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストの更新が含まれているはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタム エージェントのアクセシビリティ パターン、ARIA 属性、キーボード操作、セマンティック HTML、local storage による設定の保存が反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更を stage して commit します。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat の agent mode で進行中のセッションを監視して方向付けました。編集を確認して受け入れるか元に戻し、コンテキストを保ったまま追加のプロンプトで作業を拡張しました。

この演習では、次のことを行いました。

- エージェントの作業をリアルタイムで監視しました。
- 個々の編集を受け入れるか元に戻しました。
- 追加のプロンプトで、作業中のセッションに指示しました。
